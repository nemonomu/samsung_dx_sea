# Walmart TV DB 저장 복구

상품 상세값을 이미 수집했는데 DB 연결이 종료된 경우, 같은 데이터를 다시 저장한다.
웹사이트를 재조회하지 않으므로 재시도 중 가격이나 리뷰가 현재값으로 바뀌지 않는다.

## 실행 순서

1. 상품별 마스터·상세 저장에서 연결 오류만 최대 3회 시도한다(대기 1초, 2초).
2. 실패한 연결은 폐기하고 새 연결로 같은 데이터를 저장한다.
3. 계속 실패하면 수집 데이터와 최초 저장 시각을 메모리·파일에 보관한다.
4. **다음 상품과 다음 묶음 처리를 계속한다. 재저장 성공이 전체 실행을 종료하지 않는다.**
5. 전체 상품 및 상세 수집 재시도 대상까지 처리한 뒤, 연결 오류로 남은 저장 실패 건을
   한 번 더 순회한다. 이때도 각 저장 작업은 최대 3회로 제한한다.
6. 최종 미저장 건이 있으면 상세 단계 결과를 실패로 반환한다. 기존 통합 실행의
   `detail: FAIL`과 보고서 누락 집계에 반영된다.

데이터 형식·SQL 오류는 연결을 바꿔도 해결되지 않으므로 자동 반복하지 않는다.
DB 장애가 계속되면 전부 저장된다고 보장할 수는 없지만, 남은 상품의 처리를 건너뛰지
않으며 저장 실패 데이터가 보관된다. 파일 보관에도 실패하면 별도 오류를 남긴다.

## 중복 방지

상세 INSERT는 계정·배치·상품 URL 기준으로 기존 행을 확인한다. 저장은 성공했지만
COMMIT 응답만 유실된 경우, 재연결 후 확인된 행을 다시 INSERT하지 않는다.
이때 가격·리뷰·순위·수집 시각 등 실제 저장할 필드 전체를 DB의 자료형에 맞춰 비교한다.
값이 다르거나 같은 식별 조건의 행이 여러 개이면 충돌로 처리하고 기존 행과 보관값을
유지한다. 자동 덮어쓰기나 중복 INSERT는 하지 않는다.
같은 복구 로직끼리 동시에 INSERT하지 않도록 트랜잭션 잠금을 사용하며 잠금 대기는
5초로 제한한다. UPDATE 복구는 원래 행 ID·계정·배치로 범위를 제한한다.
기존 마스터의 정상 SKU·화면 크기를 덮어쓰는 동작은 추가하지 않는다.

## 실행 종료 후 복구

실패 데이터는 프로젝트 루트의 `recovery/walmart_tv/*.pending.json`에 보관된다.
이미 같은 배치·상품의 보관 파일이 있으면 최초 파일을 교체하지 않는다. 현재 저장하려는
값이 최초 보관값과 다르면 DB 쓰기 전에 충돌로 중단하고 다음 상품 처리를 계속한다.
정상 재저장은 메모리 또는 파일에 있는 값을 사용하며 사이트를 다시 수집하지 않는다.
복구에 성공한 파일은 `.saved.json`으로 변경된다. 이 폴더는 Git 추적과 기존 로그
자동 정리 대상에서 제외된다. 자동 최종 복구는 현재 실행에서 실패한 건만 처리한다.

이전 실행의 보관 데이터를 적재하려면 원래 크롤러가 끝난 뒤 프로젝트 루트에서 실행한다.

```powershell
python -m walmart.tv.wmart_tv_replay_saves --batch-id <복구할_배치_ID>
```

테스트 테이블의 보관 건만 복구하려면 `--test`를 붙인다. 다른 배치나 다른 모드의
데이터는 처리하지 않는다. 사이트 재수집·목록 재수집·이메일 발송은 하지 않는다.
당시 수집값과 배치, 최초 저장 시각을 사용한다. 정상 SKU나 기존 행을 자동 교체하지 않는다.
새 기능을 적용하기 전에 발생해 데이터 파일이 없는 과거 누락은 이 명령으로 복원되지 않는다.

DB 저장은 성공했으나 보관 파일의 완료 처리만 실패하면 `DB SAVED / FILE PENDING`을
표시하고 다음 상품을 계속 처리한다. 통합 보고서에도 상품 미적재와 별도로
`DB 적재 성공·복구 파일 정리 필요` 건수를 표시한다. 재적재 명령의 최종 요약은
`DB saved`, `DB failed`, `File cleanup pending`을 분리하며, 파일 정리가 남으면
미완료 종료 코드를 반환한다. 같은 명령을 다시 실행하면 INSERT 대상은 DB 값이 같은지
확인한 뒤 중복 적재 없이 파일 완료 처리만 수행한다.

보관 파일은 같은 볼륨 내 완성된 임시 파일을 새 이름으로 게시해 최초 파일을 보호한다.
파일시스템에서 이 작업이 지원되지 않거나 쓰기 권한이 없으면 파일 보관 오류를 알리고,
현재 실행에서는 메모리에 유지한 데이터로 최종 재저장을 시도한다.

파일에는 저장 대상 상품 필드만 보관하며 DB 설정·인증 헤더·HTTP 응답 전체는 넣지 않는다.
이 기능은 실패 처리 시점에 파일을 남긴다. 그 이전의 강제 종료·전원 차단까지 보장하는
전체 수집 데이터 기록 기능은 아니다.

## 오프라인 검증

```powershell
python -B -m unittest walmart.tv.test_wmart_tv_save_recovery -v
```

실제 DB·사이트·설정 파일을 사용하지 않고 연결 종료, 응답 유실, 최종 실패, 파일 오류,
후속 상품 계속 처리, 원본값 재적재를 가짜 DB로 검사한다.
